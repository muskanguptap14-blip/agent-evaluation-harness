Agent Eval Harness

Product Requirements — a lightweight developer tool for testing AI coding agents against Python tasks and test suites.
AudiencePython developers testing AI coding agents
Core goalMeasure reliability, failures, and token cost
Demo scopeShort agent tasks with clear scoring

The Core Journey

1
Open the harness and define a task or prompt.
2
Choose quick prompt mode or a structured challenge file.
3
Run the agent in a sandbox and monitor the work.
4
Execute automated checks and capture pass/fail results.
5
Review requirement-by-requirement scorecard and token usage.
6
Refine prompts or constraints and retry.

Screens and Layout

  • Task input panel — quick prompt or challenge file upload/selection
  • Run monitor — current task status and active changes
  • Evaluation results — requirement scorecard, pass/fail matrix, and summary totals
  • Metrics panel — token usage, success rate, and run health

Look and Feel

The product should feel like a practical developer utility: minimal, transparent, and honest about failure. It should feel like a debugging interface for AI workflows: readable, structured, and efficient, with clear signals over visual flair.

Features and Behavior

Task Setup and Run Control
  • The user can enter a quick prompt or load a challenge file containing multiple prompts or assertions.
  • There is a clear “run” action and visible status during the task execution.
Live Transparency
  • The user can see what the agent is doing while the run is in progress.
  • Key changes are visible without requiring a full log dump.
Automated Evaluation
  • Once complete, the harness runs automated checks.
  • Each requirement or evaluation clause is shown as pass/fail.
Metrics and Cost Visibility
  • Token usage is visible alongside the result summary.
  • The user can understand both correctness and cost at a glance.

States and Boundaries

  • Idle — ready to define a task or challenge.
  • Running — agent is working and status is visible.
  • Evaluating — tests are being run and metrics are being assembled.
  • Completed — scorecard and token summary are available.
  • Failure — required checks failed or the run did not complete successfully.
  • Empty state — clear prompt to begin; no confusing blank screen.
